# Pixel Motion Suite 2.3.18 · Android 17 / API 37

Pixel Motion Suite 是用于 LSPosed 的 Android 模块。它为 Pixel 启动器提供应用打开和回桌动画、分层图标与多任务 Dock，并为支持的系统提供十秒全屏息屏壁纸。当前桌面动效适配 Pixel Launcher 17（versionCode 907）。启用对应功能时，在 LSPosed 中选择 Pixel 启动器、系统界面和 Android 系统的相应作用域，并重启使模块加载。

## 2.3.18 恢复应用关闭时的桌面整体下沉

2.3.17 的恢复逻辑在启动器进入 `NORMAL`、恢复 Activity 或接收代理触摸时提前释放了桌面上移偏移。上滑回桌时这些事件发生在手势准备阶段，导致松手后可见的整体下沉被提前消耗。现在上滑和侧滑返回仍由各自的回桌动画启动下沉，窗口重新获得焦点时补齐没有经过这些动画的回桌路径。触摸和其他桌面状态切换只在启动器实际持有窗口焦点时恢复偏移，保留位置、速度连续接管和最终归位。

普通上滑关闭应用时，下沉起始距离重新使用旧版的松手速度公式：`60dp × (0.2 + 0.9 × |velocity| / 22)`，并保留桌面行距梯度和底栏偏移。一次完整打开留下的固定抬升位置不再覆盖本次手势结果；正在播放时的连续打断仍从当前位移和速度交接。拖动距离继续参与图标落地回弹的计算。

版本号 2.3.18，数字版本号 60。`python test/home_interruption.py <工具目录>` 增加手势准备、后台代理触摸、窗口焦点及回桌恢复的回归检查；`python test/workspace_motion.py <工具目录>` 覆盖不同手势下沉距离、动画中途反向和最终归位。真机同等上滑距离下，400ms 与 120ms 的输入分别得到 62px 和 116px 的下沉幅度；连续点击、上滑及换页后启动器进程保持正常，桌面图标、底栏和搜索栏归位。

## 2.3.17 的桌面动画打断修复

桌面错落位移使用独立偏移量叠加到启动器的位置上，开关应用动画交接时从当前偏移和弹簧速度接续。系统改变布局时，动画完成后归还最新布局位置。换页后的旧页偏移和裁切范围会清理。回桌缩放结束时，仅在实际仍处于桌面状态时补齐正常缩放值。

回桌浮动图标播放过程中，桌面触摸可以进入原生点击和滑动处理，图标继续播放至落点。开始另一应用或切换到其他桌面状态时，通过原生回调结束旧浮动图标。本版提供桌面位移接续和回桌触摸处理，应用窗口之间的位置、大小及速度接续仍需适配系统窗口动画。

修复两项辅助处理在 Android 17 上的加载异常。浮动监听层的 `mIsOpen` 从声明它的 `AbstractFloatingView` 读取，桌面、底栏和状态管理器字段从 `Launcher` 读取。启动器日志中的 `Home touch continuation ready` 和 `Reveal scale cleanup ready` 可核对成功加载。

针对 Pixel Launcher 907，版本号 2.3.17，数字版本号 59。使用发布证书覆盖安装后重启启动器。本地验证使用 `python test/workspace_motion.py <工具目录>` 和 `python test/home_interruption.py <工具目录>`，覆盖连续反向、布局更新、换页、旧回调、真实继承关系、浮动图标作用范围和缩放所有权。真机已确认两项辅助处理成功加载，复测回桌途中点击、滑动、再次打开同一应用和桌面换页后，桌面元素归位正常，未出现本模块加载错误或启动器崩溃。用户已确认前期测试版修复桌面元素错位。

## 2.3.16 的窗口裁切与上滑手势

从桌面、底栏或抽屉打开应用时，窗口内容重新使用 Pixel 启动器计算的裁切范围。2.3.13 的 Android 10 打开时序和 2.3.14 的第 16 毫秒起步继续生效。上滑时的卡片位置处理恢复到 2.3.9，移除了 2.3.10 在左上拖动途中提前交还横向偏移的逻辑。

真机复测时，可以从桌面打开正在计时的秒表，上滑并停在多任务界面，观察卡片中的时间是否继续更新。再从同一应用分别向左上、右上甩回桌面，比较松手前的卡片轨迹。

## 图标离开桌面的第一帧

Launcher 701 启动动画组后将播放位置设到第 16 毫秒。Launcher 907 的图标打开路径先初始化浮动图标，再等待一个刷新周期才播放窗口动画。2.3.14 在匹配到 Android 10 时序的普通应用图标后，读取本次窗口动画组的实际延迟，再将外层播放位置推进到窗口动画第 16 毫秒。窗口动画继续按原来的 450 毫秒时间轴播放。启动器日志中的 `A10 icon start` 可核对本次匹配和读取的延迟。

## Android 10 图标打开时序

从主屏、桌面底栏或应用抽屉点击普通全屏应用时，使用 Pixel Launcher 701 的 450 毫秒主动画。图标上沿位于目标中心下方，或图标中心距目标中心不足一个桌面单元格高度时，横移用 250 毫秒，纵移用 450 毫秒。其余位置横移用 360 毫秒，纵移用 200 毫秒。窗口缩放持续 450 毫秒，裁切和圆角持续 375 毫秒。直接显示应用内容时，浮动图标在第 25 毫秒开始淡出，两种位置分别用 50 和 40 毫秒完成交接。有系统启动遮罩时，窗口也采用新的运动时序，遮罩沿用 Android 17 的取色、图标分层和交接逻辑。

可把同一应用分别放在桌面右下和左上，先打开一次，回桌后再点相应图标。启动器日志中的 `A10 LOWER_OR_NEAR_CENTER` 或 `A10 UPPER` 表示本次选中的时序。`python test/opening_content.py <工具目录>` 校验两段曲线、位置阈值及适用窗口。

## 横屏多任务 Dock 固定在画面右侧

以多任务卡片的旋转方向为准，将画面右侧映射到启动器窗口。正反横屏均从右侧进出，图标及点击区域随 Dock 一同移动；竖屏保留底部 Dock 与搜索栏。多任务设置页移除「任务卡片滑动手势」及「卡片布局与清除按钮」两项入口，不改旧版已保存的偏好。方向回归测试：`python test/dock_edge.py <工具目录>`。

## 沿用 2.3.9：分开处理斜抛回桌和水平快切

竖屏内屏的全手势模式下，只复核原生已判为 NEW_TASK 的向上快速松手：若末速度偏离水平线超过 15°，且系统允许回桌，改走原生 HOME 链路。15° 内保持原判；慢拖、停顿、向下、触控板、横屏和系统禁止回桌时不改判。跟随桌面图标动效开关。不扩张触摸区域，不强行让边缘任务翻页。

为排查向左甩的手感，启动器每次启动最多记录六次触屏左上快抛。`PixelFling239` 记录手指和窗口中心的相对横移、松手方向及目标，并对单窗口回桌弹簧记录前约 16、48、96 毫秒的位置。这里测的是启动器提交的窗口几何，不是屏幕录像；缺少观测记为缺失，不补零。日志不包含应用名或触摸内容。息屏沿用 2.3.7。

## 沿用 2.3.8：回桌斜抛方向

在 Pixel Launcher 17（907）开启图标动效后，仅对启动器已判为快速回桌的窗口弹簧，保留原生总初速、恢复松手时的二维方向。正上抛、慢拖松手、切换应用、进入多任务和画中画均不修改。保留当前图标落点、缩放及前后景回弹。方向修正只作用于起步，不让窗口绕过图标落点自由飞出。可用 `python test/home_fling.py <工具目录>` 回归速度与作用范围。

## 沿用 2.3.7 的息屏改动

电源键息屏和黑屏抬手使用同一亮度下限 0.025。2.3.6 真机记录表明，前者在息屏动画开始时处于非交互的 ON 状态，约四秒后才变为 DOZE；前四秒请求仍是 0.0。2.3.7 仅在电源键触发、新一轮全屏 AOD 的开场阶段补上这次请求；首次进入真正的 Doze、黑屏、脉冲、离开 AOD 后立即结束开场资格。通知若复用开场的 ON 状态，则重新发送原生亮度。没有改变屏幕状态、动画时序、壁纸颜色或十秒计时。

「息屏显示 → 提高息屏面板亮度」默认开启。仅在上述电源键开场或可见的 DOZE/DOZE_SUSPEND，且内屏非交互时，把 SystemUI 发给 DreamManager 的有效亮度请求下限设为 0.025；不降低原本更高的请求。未修改全局亮度滑块或壁纸像素。通知脉冲、指纹、常规亮屏和 OFF 请求不提亮。关闭开关后，下次息显沿用原来的系统请求。

本机原始 Doze 请求为 0.0，显示服务估算为 2 nit，20 倍 RGB 也未改变此值。可用 `dumpsys display` 的内屏 `state=DOZE` 事件核对新请求与估算 nits；`dumpsys SurfaceFlinger` 的 `powerMode=Doze` 和 `displayBrightnessNits` 提供合成器侧交叉检查。这些不是光度计实测。小米公开的 dada 驱动 `MiCode/vendor_opensource_display-drivers` 的 `dada-v-oss` 分支还定义了独立的 DOZE 高低档，面板固件可能自行限制亮度；本版不直接写入驱动，也不改变系统访问权限。

复核附件及手机实装 SystemUI：两个 APK 的哈希不同，但 `DozeTriggers`、接受脉冲的回调、`DozeMachine`、`DozeScreenBrightness` 的指令一致。实机日志记录黑屏后 `DOZE_REQUEST_PULSE → DOZE_PULSING`，原因是 `pickup`，期间显示状态为 ON，约六秒后进入 `DOZE_PULSE_DONE`。旧计时只认 AOD + Doze 显示状态，且同一场 Dream 的旧截止时间不会重置。现在仅把系统已接受的黑屏抬手请求（原因 3）转为可见 AOD，重建十秒窗口；显示过程中再次抬手不续时。通知、指纹和真正的抬手亮锁屏仍走系统原流程。到期请求黑屏 Doze，不强制设备进入深度空闲。

Android 系统附件是资源包；该机 Doze 默认浮点亮度为 0.0。SystemUI 的 `clampToDimBrightnessForScreenOff` 输出进入整个显示屏的亮度请求；不能用它独立调壁纸。Pixel 动态壁纸中的地球分包最后一遍直接采样纹理；改该着色器不能覆盖其他壁纸。本版不改两个位置，也无需扩大 LSPosed 作用域或替换系统 APK。

## 启动页图标分层

2.3.2 沿用 2.3.1 的绘制方式，把「启动页图标分层」扩展到应用抽屉的普通应用和顶部推荐应用。主屏、固定底栏和抽屉共用 Pixel 启动器本次 `FloatingIconView.fetchIcon` 返回的 `IconLoadResult.drawable`，与退出动画使用同一来源，不读取目标 APK 或猜测图标包。纯色背景沿用原色；多色或渐变背景只从背景层取主色铺满系统启动页，中心仅画原前景。更换图标包后下一次点击重新取层。只有启动页接收成功才交还原生淡出，退出动画和息屏不变。

只处理系统普通图标启动页；不更改应用专属启动图、品牌图、通知入口、文件夹、快捷方式、跨用户启动或任务快照。没有可用分层、图层晚到或窗口不匹配就回退。按单次启动标识及目标组件匹配；仅系统界面收到桌面发送的临时图层，原启动标识不被替换，应用不会收到图层或回调。没有截图、磁盘图标缓存或常驻服务。

首次安装选择 LSPosed 的 Pixel 启动器、Android 系统和系统界面，重启手机。之后单独切换此开关时只需重启启动器。验证时分别从桌面、抽屉网格和抽屉推荐行冷启动同一款有分层的应用，而非从最近任务里恢复；另测非单色背景、应用自定义启动页和返回桌面。本地验证：`python test/splash.py <工具目录>`；可选真机绘图验证：`python test/splash_device.py <工具目录> <adb序列号>`（不安装模块）。

## 沿用 2.3.0 的息屏功能

全屏息屏壁纸按 Cheese-nya/aod-wallpaper v1.0 重新移植，不叠加在 2.2.9 的显示代码上。参考仓库：https://github.com/Cheese-nya/aod-wallpaper ，main 基线 `83514ea6336316fe89820e82a3d32eedad2699fe`；核对过的上游发布 ZIP 的 SHA-256 为 `857525a404c3fcf14baf63483b6a9ee9bb84fa12b4a1f1f6ddbe655900497c78`。MIT 许可证随 APK 提供。

- 当系统常亮和全屏壁纸开关都开启时，仅让 SystemUI 的 AOD 壁纸能力判断返回支持；保留原有设置变化通知。系统壁纸服务向合资格的内屏壁纸引擎转发非 ambient 状态，使壁纸不因这次通知切换到自己的暗场景。模块不进入壁纸应用、不修改它的 SCREEN_OFF 行为，不保证每款动态壁纸都能展示同一锁屏画面。
- 可选深色遮罩沿用上游的背板透明度参数 `mBehindAlpha=0.8984375`（约 90% 黑色不透明度）。遮罩关闭时不动系统前后遮罩。息屏初始化和显示 AOD 时，保留 2.3.0 的上游钳位；面板开关在发给显示系统的请求上处理，不更改钳位函数。
- 独立保留套件的十秒功能：从内屏实际进入可见 Doze 开始计时，请求系统进入黑屏 Doze；提前唤醒取消旧计时。不强制 Android 深度空闲。关闭全屏壁纸不关闭系统普通常亮时钟。保留原有开关和 Dock 配置。
- 上游预编译的系统文件针对 Android 16，本版不替换系统文件，不写驱动节点或全局刷新率、模糊与合成器属性，不承诺物理 1 nit / 1 Hz。适配限本文版本对应的 API 37 SystemUI 和系统壁纸服务；不使用主用户的设置干预其他用户。

## 安装与验证

同签名覆盖安装，LSPosed 的全屏壁纸作用域只需 Android 系统与系统界面；使用桌面动画时保留 Pixel Launcher。重启使旧代码退出所有进程。打开全屏壁纸，锁屏观察十秒后黑屏；另测计时中唤醒不会被旧计时关屏。测试遮罩可在设置页切换后再次锁屏；不必更换壁纸。关闭全屏开关后应恢复普通息屏，不再启动套件的十秒计时。

Windows 构建：使用原工程的工具目录（`jre/`、`ecj.jar`、`r8.jar`、`platform-35/android.jar`、`framework.jar`、`aapt2.exe`）。运行 `python test/port.py <工具目录>`、`python test/run.py <工具目录>`、`python test/controls.py <工具目录>` 和 `node test/motion-ui.js`，再执行 `python assemble.py <工具目录> unsigned.apk`。安装包需用原证书签名。源码不含签名密钥。
